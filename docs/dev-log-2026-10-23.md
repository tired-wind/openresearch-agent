## 五、已知问题（接手必读）

### 1. 网页端与三层脱节（阻塞录屏）

`backend/agent_api.py` 仍然硬编码：

```python
MODEL = 'qwen3.5:4b'
subprocess.run([... '--model', MODEL], cwd=PROJECT, env=env, ...)
```

- `qwen3.5:4b` 是 **Ollama** 的模型名，而本机没装 Ollama（11434 返回 502）。
- 实测把 `qwen3.5:4b` 发给 Nightshift，它**静默回落到 Nemotron** 并返回 200，但响应里的 model 是 `nvidia/nemotron-3.5-lightning-30b-a3b`。
- 后果：网页"能跑"，但界面标注的模型名是假的。**NVIDIA 奖项要求证据无歧义，必须改成显示 trace 里实际服务的模型。**

### 2. 安全边界被绕过（本次改动引入，需修）

`agent_api.supervise` 原本用白名单剥离所有模型密钥：

```python
# Allowlist environment: no model keys, tracing tokens or paid API access.
env = {k: v for k, v in os.environ.items() if k in ('PATH','HOME','TMPDIR','LANG','LC_ALL','SYSTEMROOT')}
```

而 `scripts/run_agent.py` 新增的 `load_env()` 会**直接从磁盘读 `.env`**，绕过了这个边界。虽然只影响本机，但破坏了一个明确的安全决策。

修法建议：
1. `run_agent.py` 支持 `OPENRESEARCH_NO_DOTENV=1` 跳过自动加载；
2. `agent_api.py` 显式传 `--provider` / `--model` / `--memory-dir`；
3. 白名单只放行 `METERLESS_RUNTIME_TOKEN` 与 `METERLESS_BASE_URL`（本机回环凭据），**NVIDIA key 永不离开 Nightshift**；
4. 页面渲染 trace 中的真实模型名。

### 3. H-MEM 检索门槛是标定值，不是规范值

规范门槛 `0.35` 假设神经嵌入（真匹配语义分约 0.7）。本实现用确定性词法嵌入，语义分封顶约 0.45，因此默认 `LEXICAL_RETRIEVAL_THRESHOLD = 0.28`，`RETRIEVAL_THRESHOLD = 0.35` 保留作规范参考。理由与两个值都已写入 `docs/hmem.md` 与测试。**不要把它说成规范默认值。**

### 4. `meterless/auto` 路由会变

两次实测分别落到 `lightning-30b-a3b` 与 `super-vl-120b-a12b`。**演示与录像必须固定 `NEMOTRON_MODEL`**，别用 auto。
